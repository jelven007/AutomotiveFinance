# mootdx 数据源

mootdx 作为内置 Python 插件接入现有 Provider、同步服务、Parquet/DuckDB
和设置页能力矩阵。无需 API Key；选择 mootdx 后，请求失败或数据为空不会
自动改用 TickFlow。旧数据文件不会因切换数据源而自动重建。

## 安装与启用

1. 启动 `./dev.sh`，打开 `http://localhost:3011/settings?tab=data-sources`。
2. 在 mootdx 卡片点击「安装」。已安装时显示可用状态。
3. 点击「套用」，或在能力路由逐项选择 mootdx。七项均应为 mootdx：
   日K、除权因子、实时行情、分钟K、五档盘口、财务数据、全量分钟。
4. 在数据管理页按需同步。股票、指数、ETF 的日线和目录跟随日K源；
   财务和分钟分别使用各自配置。先用少量证券验证，再扩大范围。

手动安装（在 `backend/` 内）：

```bash
uv pip install -p .venv/bin/python -r app/plugins/mootdx/requirements.txt
uv pip install -p .venv/bin/python --no-deps -r app/plugins/mootdx/requirements-no-deps.txt
```

固定使用 `mootdx==0.11.7`、`tdxpy==0.2.7`。mootdx 元数据要求旧版 httpx，
与本应用的 httpx 要求冲突，因此插件安装器分两步安装运行依赖及主包。
本适配器使用行情协议和财务解析模块，不调用 mootdx 的 HTTP 助手，
不会为了安装插件降级应用的 httpx。此安装方式不表示 mootdx 其他模块
已在该依赖组合下验证。

可通过启动环境变量配置；`dev.sh` 也将根目录 `.env` 传入后端：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `MOOTDX_SERVER` | `117.34.114.13:7709` | 行情服务器，格式为 IP:PORT |
| `MOOTDX_FINANCIAL_SERVER` | mootdx 财务服务器配置 | 可单独指定财务服务器；本次验证为 `120.76.152.87:7709` |
| `MOOTDX_TIMEOUT` | `8` | 单次 socket 超时秒数，范围 2–60 |
| `MOOTDX_WORKERS` | `4` | 分钟/股本快照并发连接数，范围 1–8 |
| `MOOTDX_MAX_PAGES` | `64` | 每只证券每次 K 线最多分页数，范围 1–80，每页最多 800 条 |

公开服务器可能下线、限流或变更协议。默认节点仅代表本次可用，不构成
可用性保证。2026 年部分节点会返回空行情或不兼容的 K 线报文，可通过
环境变量更换同一协议的数据服务节点。连接错误会重连一次；日线和分钟
批次连续三只证券发生协议/连接错误时停止该批次，已取得的数据仍可落盘。

## 数据契约

| 数据 | 应用口径与处理 |
| --- | --- |
| 证券代码 | 带交易所后缀，如 `600519.SH`、`000001.SZ`；`000001.SH` 为上证指数，不能按裸代码混同 |
| 原始日K | 不复权价格；成交量为手，成交额为元 |
| 股票/ETF 分钟K | 北京时间无时区墙钟；上游成交量为股，除以 100 转成手；成交额为元 |
| 指数日K | 使用指数解析器和协议周期 4，避免周期 9 的成交量精度损失 |
| 指数分钟K | 上游 VOL 是成交额代理量，不能当股数使用；输出 volume=null，保留价格与成交额 |
| 实时及五档 | 上游成交量、盘口量为手；涨跌幅为小数；缺失深度字段保持 null |
| 新前缀沪市 ETF | 修正 tdxpy 对 52/53/56/58/59 前缀报价的十倍价格误差 |
| 除权因子 | 每十股分红、送转、配股换算为每股，与前一交易日原始收盘生成单日 ex_factor |
| 除权精度 | 股票参考价保留两位小数，ETF 保留三位；同日事件合并，未来事件不进入因子 |
| 财务金额/股本 | 财务归档中的元/股，不额外放大；数值哨兵转 null，真实零值保留 |
| 财务百分比 | ROE、毛利率、同比等按百分数，如 16.75 表示 16.75%，不同于实时涨跌幅的小数 |
| 财务时点 | `period_end` 是报告期；`announce_date` 来自 FINVALUE col314，缺失、早于报告期或晚于当前日期的记录不进入历史表 |

财务按 FINVALUE 数字列映射，避免上游中文重名列将累计值替换成单季度值。
支持 metrics、income、balance_sheet、cash_flow、shares 五张表。财务归档
缓存位于 `data/cache/mootdx/financial/`，下载有超时、大小边界、MD5 校验和
原子替换。即时 finance 快照仅用于当前标的股本及上市日期；其金额字段
未通过本次单位核验，不用于财务报表或历史股本回填。

## 功能覆盖与边界

| 功能 | 当前状态 |
| --- | --- |
| 沪深股票、指数、ETF 目录与日线 | 已适配，继续使用现有独立资产存储目录 |
| 前复权、日线指标及策略数据输入 | 沿用原有 enriched 计算；依赖历史覆盖和因子完整度 |
| 分时图、分钟同步/回测数据输入 | 支持 1m、5m、15m、30m、60m；分钟回溯受服务器保留量限制 |
| 实时行情与五档盘口 | 已适配；公开协议快照不是逐笔流，盘中延迟及全市场吞吐未完成实盘压测 |
| 财务分析 | 已适配五张表；最新查询最多检查近四期，历史查询最多近八期 |
| 全量分钟 | 实际逐证券并发拉取当天 1m 数据，走现有批量修复路径；没有伪造增量端点 |
| 北交所 | 当前 tdxpy 标准行情接口不支持，不声明已覆盖 |
| 09:25 竞价终态 | 交易日 09:25:08 起从当前沪深在市目录自动采集，三次有界重试，按日原子落盘；只能从启用日起积累 |
| 龙虎榜、启用前的历史竞价 | 当前 mootdx 插件未提供；普通分钟 K 线不能替代竞价历史 |
| 行业/概念成分 | 插件没有补齐相应历史维表；相关分析仍依赖项目已有维表覆盖 |
| 名称、ST/退市状态 | 每次成功目录同步写入 SCD2 历史；首次启用前的状态无法从 mootdx 自动补齐 |

全量分钟修复模式的有效刷新间隔至少 60 秒；界面中更短的偏好值不会让
mootdx 获得秒级全市场推送能力。界面公布的 30 天分钟范围是请求上限参考，
不是每只证券均有 30 天历史的保证；长假、停牌和服务端截断会缩小覆盖。

实时/盘口的 timestamp 是系统取得数据的时间，不是已核验的交易所行情
生成时间。休市时服务器可能返回上一交易日快照，不能据此认定今天成交，
也不能把抓取时点当成历史竞价可见时点。

竞价采集额外校验通达信服务端时间处于 09:25–09:30、快照昨收与本地上一
交易日日线一致、返回覆盖率不低于 95%。任一条件失败均不发布分区。
标的池要求当日更新的沪深股票目录，并剔除名称标记为退市/摘牌的证券；
目录过期时保留已有历史并停止当日采集。落盘位置为
`data/auction_snapshot/date=YYYY-MM-DD/`，`metadata.json` 与 Parquet 的
`capture_id` 一致才视为完整发布。

2026-10-07 休市日实测返回 5,065 条旧会话报价，服务端时间匹配率为 0、
昨收匹配率约 8.35%，采集器按预期拒绝落盘。首个真实交易日仍需核对竞价价、
竞价量与交易终端的一致性；校验通过前不将其用于自动交易。

财务归档可能被上游重述，原公告日过滤不等于恢复了当年的原始版本。
证券目录成功同步后会把名称、ST/风险警示、上市状态和上市日期变化写入
`data/instrument_status/history.parquet`，并在 enriched 中记录对应状态及
`instrument_status_known`。该模型只保证首次启用后的时点一致性，无法恢复更早
状态；严格回测仍需要可信历史来源、交易规则和竞价采集。
ETF 特殊拆分若未在服务器除权事件中返回，也无法从空表推断已完整处理。

原有行情文件，也没有替用户执行全市场重建。

出现 mootdx 卡片与七项候选；后续自动化连接超时，因此「套用」按钮修复后

分钟 1200 行、除权因子 2 行、实时 1 行、五档 1 行、全量分钟试拉 1200 行、
