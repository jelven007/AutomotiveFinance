# 公网部署: 邮箱账户初始化

系统使用邮箱和密码登录。浏览器注册必须先向该邮箱发送 6 位验证码并完成校验。所有账户共享同一套行情、策略和系统配置, 暂不区分角色或租户。

## 方式一: 浏览器注册

首次打开系统会直接显示注册页:

1. 输入邮箱并点击“发送验证码”。
2. 输入邮件中的 6 位验证码和至少 8 位的密码。
3. 验证码校验成功后创建账户并自动登录。

验证码 10 分钟有效, 60 秒内不能重复发送, 连续输错 5 次后失效, 且成功注册后不能再次使用。公开发送接口按来源 IP 限制为每小时 10 次。

全新部署要使用浏览器注册, 需先在 `.env` 配置注册邮件 SMTP:

```bash
AUTH_SMTP_HOST='smtp.example.com'
AUTH_SMTP_PORT=465
AUTH_SMTP_SECURITY='ssl'       # ssl | starttls | none
AUTH_SMTP_USERNAME='no-reply@example.com'
AUTH_SMTP_PASSWORD='SMTP 密码或授权码'
AUTH_SMTP_FROM_ADDRESS='no-reply@example.com'
```

`AUTH_SMTP_HOST` 非空时整组环境变量优先。留空时, 系统会尝试复用“设置 → 监控与通知”中已保存的邮件 SMTP, 主要用于已有账户后继续开放注册。新安装尚不能进入设置页, 因此必须配置环境变量或使用下方的预置账户方式。

## 方式二: 环境变量预置

自动化部署可在 `.env` 或运行环境中同时设置:

```bash
AUTH_EMAIL='admin@example.com'
AUTH_PASSWORD='至少八位的密码'
```

服务首次启动时会:

1. 规范化邮箱并校验密码长度。
2. 使用 PBKDF2 哈希密码后写入 `data/user_data/auth.json`。
3. 将账户文件权限设为 `600`。
4. 已有账户时跳过初始化, 不覆盖页面中修改过的密码。

预置账户属于部署初始化, 不经过公开注册接口, 因此不要求邮箱验证码或 SMTP。后续用户从浏览器注册时仍必须完成验证码校验。

`.env` 应保持 `600` 权限且不得提交到 Git。密码含 `$` 等字符时建议使用单引号。

## 旧版访问密码迁移

升级前已设置访问密码的部署无需重置。新登录页会显示“升级现有账户”:

1. 输入要绑定的邮箱。
2. 输入原访问密码。
3. 绑定完成后使用邮箱和原密码登录。

迁移只改变认证文件结构, 不修改行情、策略、自选或系统设置。

只设置 `AUTH_PASSWORD` 而未设置 `AUTH_EMAIL` 时, 系统也会进入这一兼容模式。

## 修改和重置

- 修改密码: `设置 → 账户 → 修改密码`。成功后该账户的全部会话会退出。
- 退出登录: 使用侧栏底部的退出按钮或账户设置页。
- 忘记密码: 当前验证码只用于注册, 不提供邮件找回。停服并备份后删除 `data/user_data/auth.json`, 重启后重新注册或通过环境变量预置账户。

```bash
cp data/user_data/auth.json data/user_data/auth.json.bak
rm data/user_data/auth.json
```

删除认证文件会移除全部登录账户, 但不会删除其他业务数据。

## 安全建议

- 公网部署必须使用 HTTPS。
- 密码建议使用 12 位以上随机字符串。
- `auth.json`、`auth_verifications.json` 和 `.env` 不应进入 Git 或公开备份。
- SMTP 密码优先使用邮件服务商提供的独立授权码, 不要使用邮箱主密码。
- API Token 是外部程序调用通道, 与浏览器邮箱账户相互独立。
