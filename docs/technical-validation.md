# 技术方案复核与修正

本次基于当前工作区代码校验，保留已有 mootdx 插件开发。核心修复属于 L3：
现有 Provider 接口能够表达数据能力，但同步层的跨源回退和权限门控需要直接修正。

## 修正后的架构约束

- 保持模块化单体。部署约束为单个 API/调度服务主进程；回测仍使用隔离的
  `spawn` 计算子进程。不能把“服务主进程唯一”解释成禁止计算子进程。
- EventBus、SSE ticket、内存限流和调度状态尚未外置，不能直接增加 Uvicorn
  worker 或并行部署多个服务实例来扩容。
- 数据集按用户配置独立选源；能力缺失、依赖缺失与空结果都不等于允许换源。
  空除权因子表也不能证明没有除权事件，更不能自动从另一供应商补入。
- 不通过改默认配置、删除其他 Provider 或覆盖用户历史数据来实现单一来源。
  使用 mootdx 时需将相关能力路由到 mootdx，并确认能力矩阵及数据覆盖。
  已有磁盘数据仍需单独核验来源；本轮没有迁移或重建用户数据。

## 已修复的运行问题

| 触发条件 | 原问题 | 修复 |
| --- | --- | --- |
| 插件缺依赖后重启 | 读取偏好将已知插件改判为 TickFlow | 保留已知插件身份，由能力层报告不可用 |
| 所选源无标的接口或请求失败 | 股票标的同步偷偷回退 TickFlow | 返回空结果，保留原维表 |
| 沪深目录部分失败或分页截断 | 非空但不完整的列表可能覆盖完整维表 | 沪深完整性检查；协议目录计数与唯一代码数校验 |
| 同步指数或 ETF | 目录和日K绕过所选 Provider，还受 TickFlow 权限限制 | 复用日K源，透传资产类型，分开保存 |
| 自定义 ETF 因子返回空表 | 自动调用 TickFlow 因子接口 | 保留所选源及原因子文件 |
| 单股即时除权查询 | 固定调用 TickFlow | 走所选除权源 |
| 分钟源解析、请求或时间口径失败 | 转入 TickFlow 分钟调用 | 隔离失败、保留本地数据，API/监控门控一致 |
| 全量分钟源不可用 | 在另一个源上执行修复或增量轮 | 中止本轮并在状态中报告错误 |
| 实时或财务源未加载/缺能力 | 继续尝试 TickFlow | 中止该次拉取，保留缓存或本地数据 |
| UTC 服务器同步标的和默认日线窗口 | 使用服务器本地日期/时间 | 使用北京时间 |
| 前端执行全量测试 | 两个文件使用 Node runner，Vitest 无法识别 | 统一为 Vitest，并将全量测试加入 CI |
| 前端执行 lint | 缺少 ESLint 与配置 | 安装锁定依赖，增加运行错误和 Hook 检查，接入 CI |
| 迷你分时图有数据→空→恢复 | 条件调用 `useId`，渐变 ID 重新生成 | Hook 始终执行，增加空态切换回归测试 |

行情与财务仍复用既有标准化、仓库写入和缓存更新链路，未新增平行存储。
旧配置继续可读，`same_as_daily` 等已废弃非法值仍按现有约定处理。
行为变化是取消“显式自定义源不可用时自动换成 TickFlow”的旧语义，
相关旧测试已改为验证保留数据和不跨源请求。

## 一进二方案的能力边界

上次分析把“没有实现 mootdx”当作当前事实已经过时：工作区现有插件需按真实代码、
依赖和协议契约验证。插件清单声明普通行情/分钟能力，并不代表竞价历史或历史
风险警示状态已具备。未建立历史数据之前，不能用代码推断或补造历史事实。

1. **昨日候选**：以实际上一交易日收盘后确认的数据生成首板集合。
   `consecutive_limit_ups >= 2` 是二板确认条件，不能当作盘前一进二入场条件。
2. **今日竞价**：09:25 是交易所时点；系统收到终态快照的时间通常更晚。
   当前已从启用日起自动归档服务端时间、接收时间、覆盖率和上一交易日匹配率。
   mootdx 不能补齐启用前的竞价终态，分钟 OHLC 仍不能替代该历史。
3. **执行时点**：看到 09:30 开盘价后产生的信号，不能再按同一个开盘价回填成交。
   应按信号产生后的首个可执行报价或下一分钟开盘模拟，并保留 T+1、
   涨跌停、停牌、费用及数据缺口约束。
4. **历史维表**：现有名称/ST 信息主要是当前快照。追加按日快照只能改善未来
   积累，无法修复过去缺失的状态。严格历史样本还需历史 ST、上市/退市、
   交易日和涨跌停规则。缺失期间的结果不能宣称满足严格时点一致性。
5. **可复现性**：数据版本、策略版本、决策时间与成交假设需要共同保存。
   `available_at <= decision_at` 是必要条件，还需数据覆盖与成交可行性验证。

因此，本轮修复提高了数据源选择和运行链路的正确性，并开始积累后续交易日
竞价历史；启用前的竞价缺口、历史 ST 补齐和严格一进二执行模型仍属于后续建设，
不能宣称已通过实盘验证。

## 验证方法

后端使用离线 Provider 和真实本地 Parquet 验证：
禁止访问 TickFlow 的负例、空/异常路径、缺依赖配置、不同资产目录隔离、
旧文件字节不变、目录截断与单位/时间口径。使用全量 pytest 检查其他模块兼容。

前端使用全量 Vitest、TypeScript/Vite 构建及 ESLint。Hook 依赖建议保留为警告，
Hook 调用顺序与基础运行错误作为 CI 阻断项；没有批量更改已有 effect 依赖，
避免为了清空告警改变请求和刷新语义。

这些检查不等价于实盘网络容量、9:25 行情终态可靠性或真实历史数据完整性测试。
