# 技术方案复核与修正

## 2026-10-08 优先级复核

结论: 保持单服务主进程的模块化单体, 继续使用已配置的 mootdx 行情/财务链路。
当前优先改善数据发布的正确性和诊断, 无需引入多实例、消息队列或平行存储。
本轮修改属于 L3, 保留工作区正在开发的策略与分钟回测变更。

| 优先级 | 已落地调整 | 验收证据 |
| --- | --- | --- |
| P0 | 中断 enriched 发布保持不可读; 读取、实时 flush、局部 upsert 均不得自动解除 | 原行为可复现 10 个失败场景, 修复后回归通过 |
| P0 | 股票中断后强制全量恢复; ETF 从全部本地日线分批暂存重建, 全部分区完成后提交 | 双资产覆盖、第二分区故障、缺失原始日期及失败重试 |
| P0 | 恢复取消保留不完整标记, 显式释放失败任务认领 | 防止 traceback 保留旧对象导致恢复持续被拒绝 |
| P0 | 目标文件替换前即标记本次发布有改动, fsync 失败不得按无写入撤销 | 故障注入复现替换成功、目录 fsync 失败后误回 ready |
| P1 | 校验 manifest 嵌套字段, 拒绝不稳定发布; 采集前后比较 generation, 最终写入持有资产锁 | 损坏清单、首次 generation 漂移、采集和提交竞态 |
| P1 | 健康检查逐项隔离异常; 失败仍返回完整诊断, 调度器查询失败不再显示正常 | 7 类依赖故障注入, HTTP readiness 语义回归 |
| P1 | 新鲜度采用已有交易日历及本地指数日期证据, 增加盘后宽限与 unknown 状态 | 人工长假、单个交易日缺失、禁止健康探针外部取数 |
| P1 | 策略目录回归按时间周期与执行接口契约验收, 移除“固定 25 个且全为日线”的旧限制 | 兼容工作区已有分钟策略, 保留日线矩阵与分钟处理函数检查 |

恢复依赖完整本地原始日线。逐分区原子替换不能提供整个数据目录的自动回滚，
失败期间可能存在混合文件; 保持不可读是必要行为。完整重建成功只证明本地
输入已重新计算并发布, 不证明原始数据已覆盖全市场所有应有记录。

manifest 是不可变的追溯清单, 底层数据仍可变化。发布锁保护 stock/ETF enriched
版本与清单提交边界, 不把其他数据集转换为事务快照。正常实时增量导致 release
漂移仍应报告, 不通过手工更新基线掩盖异常。

本轮验证: 发布/健康定向回归 99 项、策略目录兼容回归 10 项通过；
后端全量 pytest **2,667 通过、7 跳过** (153.50 秒, 92 条依赖/既有 API 警告)。
变更 Python 文件 Ruff 与 HEAD 相比新增诊断 0; `git diff --check` 通过。
本轮无前端或构建配置变更, 未重复执行前端构建或 ECS 发布。

后续优先事项:

1. 持久化带来源和有效覆盖区间的交易日历, 降低重启及长假期间的 unknown。
   目前指数历史尾部缺失不能当作休市证据。
2. 补充 SSE 终态成功/失败与首字节耗时指标。现有 HTTP 状态码无法反映响应头
   发出后的流中断, 进程内指标也不跨重启保留。
3. 如需要历史回测逐字节复现, 再引入带文件哈希和保留策略的数据快照。
   目前 release ID、generation 和策略哈希只提供追溯, 不冻结历史文件。

本轮仅修改本地代码与文档, 未操作 ECS 数据或重新部署服务。

## 既有方案基线

此前校验保留 mootdx 插件开发。核心修复属于 L3: 现有 Provider 接口能够表达
数据能力, 同步层的跨源回退和权限门控需要直接修正。

## 修正后的架构约束

- 保持模块化单体。部署约束为单个 API/调度服务主进程；回测仍使用隔离的
  `spawn` 计算子进程。不能把“服务主进程唯一”解释成禁止计算子进程。
- EventBus、SSE ticket、内存限流和调度状态尚未外置，不能直接增加 Uvicorn
  worker 或并行部署多个服务实例来扩容。
- 数据集按用户配置独立选源；能力缺失、依赖缺失与空结果都不等于允许换源。
  空除权因子表也不能证明没有除权事件，更不能自动从另一供应商补入。
- 不通过改默认配置、删除其他 Provider 或覆盖用户历史数据来实现单一来源。
  使用 mootdx 时需将相关能力路由到 mootdx，并确认能力矩阵及数据覆盖。
  已有磁盘数据仍需单独核验来源；本轮没有迁移或重建用户数据。

## 已修复的运行问题

| 触发条件 | 原问题 | 修复 |
| --- | --- | --- |
| 插件缺依赖后重启 | 读取偏好将已知插件改判为 TickFlow | 保留已知插件身份，由能力层报告不可用 |
| 所选源无标的接口或请求失败 | 股票标的同步偷偷回退 TickFlow | 返回空结果，保留原维表 |
| 沪深目录部分失败或分页截断 | 非空但不完整的列表可能覆盖完整维表 | 沪深完整性检查；协议目录计数与唯一代码数校验 |
| 同步指数或 ETF | 目录和日K绕过所选 Provider，还受 TickFlow 权限限制 | 复用日K源，透传资产类型，分开保存 |
| 自定义 ETF 因子返回空表 | 自动调用 TickFlow 因子接口 | 保留所选源及原因子文件 |
| 单股即时除权查询 | 固定调用 TickFlow | 走所选除权源 |
| 分钟源解析、请求或时间口径失败 | 转入 TickFlow 分钟调用 | 隔离失败、保留本地数据，API/监控门控一致 |
| 全量分钟源不可用 | 在另一个源上执行修复或增量轮 | 中止本轮并在状态中报告错误 |
| 实时或财务源未加载/缺能力 | 继续尝试 TickFlow | 中止该次拉取，保留缓存或本地数据 |
| UTC 服务器同步标的和默认日线窗口 | 使用服务器本地日期/时间 | 使用北京时间 |
| 前端执行全量测试 | 两个文件使用 Node runner，Vitest 无法识别 | 统一为 Vitest，并将全量测试加入 CI |
| 前端执行 lint | 缺少 ESLint 与配置 | 安装锁定依赖，增加运行错误和 Hook 检查，接入 CI |
| 迷你分时图有数据→空→恢复 | 条件调用 `useId`，渐变 ID 重新生成 | Hook 始终执行，增加空态切换回归测试 |

行情与财务仍复用既有标准化、仓库写入和缓存更新链路，未新增平行存储。
旧配置继续可读，`same_as_daily` 等已废弃非法值仍按现有约定处理。
行为变化是取消“显式自定义源不可用时自动换成 TickFlow”的旧语义，
相关旧测试已改为验证保留数据和不跨源请求。

## 时点一致性与可复现性边界

首板数量、连板梯队和 `consecutive_limit_ups` 是市场统计或通用策略输入，
不能仅凭这些字段断言实现了某个特定交易战法。具体策略以实际代码和领域
验收为准; 本轮发布与健康检查修复不对工作区新增“一进二”策略作效果结论。

1. **竞价历史**：09:25 是交易所时点，系统收到终态快照的时间通常更晚。
   当前只从启用日起归档服务端时间、接收时间、覆盖率和上一交易日匹配率。
   mootdx 不能补齐启用前的竞价终态，分钟 OHLC 不能替代该历史。
2. **执行时点**：信号形成后不能使用已知时点之前不可获得的价格回填成交。
   日线和分钟回测分别保留既有成交时点、T+1、涨跌停、停牌、费用和缺口约束。
3. **历史维表**：名称、ST/风险警示和上市状态从首次成功目录同步开始按 SCD2
   积累。`instrument_status_known=false` 的旧日期不能宣称满足严格
   Point-in-Time。
4. **可复现性**：成功的数据发布写入全局 release manifest；回测结果记录
   release ID、enriched generation、配置哈希和策略源码哈希。manifest 用于追溯
   发布状态，不把可变数据目录转换成不可变快照；generation 不一致会明确标记。

## 验证方法

后端使用离线 Provider 和真实本地 Parquet 验证：
禁止访问 TickFlow 的负例、空/异常路径、缺依赖配置、不同资产目录隔离、
旧文件字节不变、目录截断与单位/时间口径。使用全量 pytest 检查其他模块兼容。

前端使用全量 Vitest、TypeScript/Vite 构建及 ESLint。Hook 依赖建议保留为警告，
Hook 调用顺序与基础运行错误作为 CI 阻断项；没有批量更改已有 effect 依赖，
避免为了清空告警改变请求和刷新语义。

开放 API 契约使用“稳定字段明确、加法字段透传”的兼容策略。模型序列化不会把
处理函数未返回的可选缺省字段注入旧响应。`test_openapi_contract.py` 同时检查
端点集合、成功响应 schema 和裁剪后的 Tier A schema 指纹，避免无意改变二开方
和 MCP 依赖的边界。

HTTP 观测测试覆盖调用方请求 ID 继承、非法值重生、日志上下文、路由模板聚合、
认证层 401/403、未处理异常 5xx 和指标重置。诊断接口不进入公开白名单和 Tier A
Token 面；指标不记录 query、body 或认证信息，并明确是随进程重启清零的本地状态。

这些检查不等价于实盘网络容量、9:25 行情终态可靠性或真实历史数据完整性测试。
